## 如何向 AI 共享

> 请读取这份个人档案，并在本次对话中参考其中的背景与协作偏好。若无法访问链接，请告诉我，我会粘贴正文。占位示例不能视为我的真实资料；需要更新档案时，请先提出修改建议。

README 链接：<https://github.com/tommytien-source/ai-personal-profile/blob/main/README.md>

此仓库提供统一的资料来源；不同 AI 是否能读取链接、保留上下文，取决于各自的功能。更新 GitHub 后，需让对应 AI 重新读取最新版本。

## 待办跟踪

使用本仓库的 [Issues](https://github.com/tommytien-source/ai-personal-profile/issues) 管理补充与修订：

1. 新建 Issue，选择“档案待办”模板。
2. 写明要更新的章节、具体内容与完成标准。
3. 用复选框记录进度；提交修改时，在提交说明中引用 Issue 编号，例如 `docs: update profile (#1)`。
4. 更新完成后关闭 Issue，需要继续处理时可重新打开。

## 本地同步与版本管理

Git 会记录已提交的文件版本，无需另行开启版本开关。请将每次需要保留的修改提交为独立 commit，并填写清楚的提交说明。

### 首次下载

```bash
git clone https://github.com/tommytien-source/ai-personal-profile.git
cd ai-personal-profile
```

### 修改前同步，修改后提交

```bash
git pull --ff-only origin main
# 编辑 README.md 并保存
git add README.md
git commit -m "docs: update personal profile"
git push origin main
```

推送前需使用具有仓库写入权限的 GitHub 账号完成 Git 身份验证。GitHub 网页编辑文件时，也应提交修改以保留版本记录。

### 查看历史与回退

```bash
git log --oneline
git show <commit-sha>
# 撤销某次普通提交，并创建一条新的回退记录
git revert <commit-sha>
git push origin main
```

将 `<commit-sha>` 替换为历史记录中的提交编号。若出现冲突，按 Git 提示处理；使用 `git revert` 可保留既有历史与回退过程。

网页查看：[提交历史](https://github.com/tommytien-source/ai-personal-profile/commits/main/)。
